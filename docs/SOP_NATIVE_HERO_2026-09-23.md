## Диагностика / DRY_RUN

Desktop первого экрана состоял из hero-approved-reference-v7.webp с растровым текстом и прозрачными ссылками-hotspot. Соотношение сторон 1672/941 определяло размеры всей композиции; поля заполнялись размытой копией картинки. Мобильная версия дублировала контент; старый hero оставался скрытым в DOM.
План: заменить только opening-scene на единый HTML-компонент, подключить изолированные стили в head и исключить активное подключение hero-static-cover-v6.css. Остальные страницы, разделы, ссылки приёма обращений, настройки домена и SEO остаются прежними.

## Изменение

- `_includes/hero-native.html`: единый h1, текст, навигация и CTA для всех размеров экрана. Работают без JavaScript.
- `assets/hero-native.css`: адаптивная сетка, естественная высота при нехватке места, видимый keyboard focus и hover, перенос кнопок и навигации.
- `index.html`: Liquid заменяет целиком исходный opening-scene, а не дописывает перед скрытым блоком; CSS подключён в head.
- Иллюстрация показана отдельно: CSS вырезает область (724,120)–(1495,905) существующего утверждённого изображения, сохраняя пропорции. Растровые надписи и кнопки не попадают в видимую область. Новый герб или символика не добавляются; исходный файл не изменяется.
